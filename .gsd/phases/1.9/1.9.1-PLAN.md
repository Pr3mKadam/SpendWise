# Plan 1.9.1: Recurring Automations Engine

## Objective
Implement a local rule engine that automatically generates transactions for recurring bills, subscriptions, and periodic budget resets. This feature must work entirely offline using a background worker or periodic checks on app launch.

## Context
- `src/store/useStore.ts` (Zustand store)
- `src/types/index.ts` (Transaction types)
- `src/components/views/RecurringView.tsx`

## Tasks

<task type="auto">
  <name>Define RecurringTransaction types and store schema</name>
  <files>src/types/index.ts, src/store/useStore.ts</files>
  <action>
    - Add `RecurringTransaction` interface: `id, merchant, amount, category, frequency (daily|weekly|monthly|yearly), lastProcessed, nextOccurrence`.
    - Add `recurringTransactions: RecurringTransaction[]` to the Zustand store state.
    - Add actions: `addRecurringTransaction`, `removeRecurringTransaction`, `updateRecurringTransaction`.
  </action>
  <verify>
    npx tsc --noEmit
  </verify>
  <done>Types are defined and store actions are correctly typed without breaking compilation.</done>
</task>

<task type="auto">
  <name>Implement the Automation Logic (Processing Engine)</name>
  <files>src/hooks/useAutomations.ts, src/components/layout/MainShell.tsx</files>
  <action>
    - Create a hook `useAutomations` that runs on app mount.
    - It should check `recurringTransactions` where `nextOccurrence <= Date.now()`.
    - For each match:
      1. Create a new `Transaction` in the store.
      2. Update `lastProcessed` and calculate the new `nextOccurrence` based on frequency.
    - Ensure it handles "missed" occurrences gracefully (e.g., creating multiple transactions if a monthly bill was missed for 2 months).
    - Integrate `useAutomations()` into `MainShell.tsx` so it runs once when the app is launched.
  </action>
  <verify>
    npx tsc --noEmit
  </verify>
  <done>Automation engine correctly generates transactions based on schedules and is integrated into the app lifecycle.</done>
</task>

## Success Criteria
- [ ] Users can define recurring transactions in the store.
- [ ] Transactions are automatically generated when due upon app launch.
- [ ] Logic correctly calculates next occurrences for all frequencies.
- [ ] Zero external dependencies used for timing.
