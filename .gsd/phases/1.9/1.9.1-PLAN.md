# Plan 1.9.1: Recurring Automations Engine

## Objective
Implement a local rule engine that automatically generates transactions for recurring bills, subscriptions, and periodic budget resets. This feature must work entirely offline using a background worker or periodic checks on app launch.

## Context
- `src/store/useStore.ts` (Zustand store)
- `src/types/index.ts` (Transaction types)
- `src/hooks/usePersistence.ts`

## Tasks

<task type="auto">
  <name>Define RecurringTransaction types and store schema</name>
  <files>src/types/index.ts, src/store/useStore.ts</files>
  <action>
    - Add `RecurringTransaction` interface: `id, amount, category, description, frequency (daily|weekly|monthly|yearly), lastProcessed, nextOccurrence`.
    - Add `recurringTransactions: RecurringTransaction[]` to the Zustand store.
    - Add actions: `addRecurring`, `removeRecurring`, `updateRecurring`.
  </action>
  <verify>
    `npx tsc --noEmit` passes. Store state includes the new array.
  </verify>
  <done>Types and store actions implemented.</done>
</task>

<task type="auto">
  <name>Implement the Automation Logic (Processing Engine)</name>
  <files>src/hooks/useAutomations.ts</files>
  <action>
    - Create a hook `useAutomations` that runs on app mount.
    - It should check `recurringTransactions` where `nextOccurrence <= Date.now()`.
    - For each match:
      1. Create a new `Transaction` in the store.
      2. Update `lastProcessed` and calculate the new `nextOccurrence` based on frequency.
    - Ensure it handles "missed" occurrences if the app wasn't opened for a long time (e.g., creating multiple transactions if a monthly bill was missed for 2 months).
  </action>
  <verify>
    Create a mock recurring transaction set for 1 minute in the past.
    Refresh app -> check if a transaction was automatically created.
  </verify>
  <done>Automation engine correctly generates transactions based on schedules.</done>
</task>

## Success Criteria
- [ ] Users can define recurring transactions.
- [ ] Transactions are automatically generated when due upon app launch.
- [ ] Logic correctly calculates next occurrences for all frequencies.
- [ ] Zero external dependencies used for timing.
